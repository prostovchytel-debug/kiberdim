# КіберДім · Навігатор знань

Окрема освітня платформа: статичний клієнт на GitHub Pages, дані та API — у Supabase. Попередній сайт не замінюється.

## Можливості цієї версії

- Вхід учня без облікового запису: PIN із 6 цифр, клас, прізвище та ім’я.
- Профілі адміністратора, вчителів та учнів. Адміністратор також працює як учитель.
- Приватні тести, п’ять типів запитань, бали та час для кожного запитання, випадкова вибірка за розділами.
- Одиночний вибір, множинний вибір, відповідність, послідовність, категорії зі словами, які можна залишити у хмарі.
- Запуск для обраних класів, пауза, відновлення, завершення або скасування сеансу.
- Звіти, журнал за сеансами, CSV, рекомендації та карти досягнень за предметами.
- Зображення HTTPS / Google Drive. Ключі відповідей зберігаються лише на сервері.

## Імпорт Excel і видалення

Адміністратор відкриває **Користувачі → Імпорт з Excel**, завантажує шаблон учнів або вчителів і заповнює його. Підтримуються `.xlsx` та `.xls` до 5 МБ, до 500 користувачів з одного обраного аркуша.

- Учні: `ПІБ`, `Клас`, необов’язковий `Логін`.
- Учителі: `ПІБ`, `Предмети` (через крапку з комою), необов’язковий `Логін`.
- Порожні логіни генеруються автоматично. Нові класи й предмети створюються під час імпорту.
- Попередній перегляд показує помилки, дублікати логінів та попередження про однакові імена. Формули потрібно замінити значеннями.
- Створення йде пакетами по 5. Після мережевої помилки можна продовжити в цьому ж вікні: ідентифікатори рядків запобігають повторному створенню.
- Після імпорту завантажте Excel із логінами й тимчасовими паролями **до оновлення сторінки або виходу**. Паролі зберігаються лише в пам’яті вкладки; сервер отримує їх для хешування, база зберігає тільки хеші. При першому вході обов’язкова зміна пароля.

Адміністратор може видаляти учнів, учителів, класи та предмети. Учитель — власні тести. Кнопка **Видалені** дозволяє відновити записи; попередні результати та звіти не стираються. Видалений користувач не може входити; його сесії авторизації відкликаються. Власний акаунт і адміністраторів видаляти не можна. Активні сеанси та залежності класу/предмета блокують видалення з поясненням; спочатку потрібно завершити сеанс або змінити прив’язки. Для відновлення користувача чи тесту спочатку відновіть необхідні класи/предмети.

`tests/admin-db.sql` перевіряє імпорт, повтор запиту, права, відновлення, збереження оцінок і транзакційність на тимчасових даних у транзакції з `ROLLBACK`.

## Правила оцінювання

Вартість кожного запитання задає вчитель. Одиночний і множинний вибір та послідовність оцінюються повністю за точно правильної відповіді; відповідність і категорії — пропорційно правильним елементам. Пропуск через таймер дає 0 балів.

Рівні: П — до 25% включно; С — понад 25% до 50%; Д — понад 50% до 75%; В — понад 75%. Бальна оцінка: `max(1, round(набрані / можливі × 12))`, максимум 12. Нуль балів за роботу відповідає оцінці 1.

Таймер перевіряється на сервері. При паузі зупиняється логічний час сеансу, відповіді блокуються. Повторна відправка вже прийнятої відповіді не нараховує бали вдруге. Після скасування колонка без завершених робіт зникає; завершені оцінки зберігаються, інші клітинки позначаються «С».

## Облікові записи й доступ

Паролі не зберігаються відкритим текстом. Використовується PBKDF2-SHA256; нові паролі — 600 000 ітерацій. Сесії мають випадкові токени, у базі зберігаються лише їхні SHA-256 хеші. Зміна пароля / блокування відкликає попередні сесії через версію доступу. Адміністратор може видати новий тимчасовий пароль; користувач обов’язково змінює його.

Усі таблиці мають RLS і закриті для прямого доступу браузера. Edge Function перевіряє роль і власника для кожного запиту. `verify_jwt=false` потрібне для власного входу за логіном та гостьового PIN: це не вимикає прикладну перевірку доступу. Service role ключ доступний лише у середовищі Edge Function. У клієнті міститься тільки публічний publishable key.

Гостьове ім’я вводить учень і воно не підтверджує особу. Такі результати позначені «Гість» і не прив’язуються автоматично до профілю за збігом імені. Для історії досягнень учень спочатку входить у свій профіль.

## Розробка

Потрібен Node.js 24. SheetJS 0.20.3 встановлюється з офіційного tarball; збірка копіює модуль Excel і ліцензію в `dist/vendor/`, тому під час роботи він завантажується з цього ж сайту.

```sh
npm ci
npm test
npm run build
```

`dist/` містить лише клієнтські файли. Сервер: `supabase/functions/quiz/`. Міграція відновлена з фактично застосованої історії Supabase.

`scripts/check-integration.mjs` запускається вручну лише з тимчасовими QA-обліковими записами, описаними у `.secrets/qa.json`; цей файл ніколи не комітиться. Тест перевіряє ролі, ізоляцію власників, усі типи запитань, повторну відправку, паузу, таймер, скасування та закритий Data API. Після перевірки QA-записи потрібно видалити.

## Публікація

GitHub Actions у `.github/workflows/pages.yml` запускає тести, збирає `dist/` і публікує GitHub Pages. У налаштуваннях репозиторію **Pages → Source → GitHub Actions** має бути ввімкнено. Серверна функція розгортається окремо в Supabase.

## Межі поточного етапу

Ця версія реалізує приватні живі тести. Публічні призначення без коду, підгрупи та маршрутизація оцінок між учителями при заміні, спільний банк тестів та уроки потребують окремого наступного етапу. Старі навчальні матеріали автоматично не імпортуються. Масове навантаження класів поки не випробуване; оновлення стану відбувається опитуванням кожні 4 секунди. Поточний журнал показує до 200 сеансів учителя.


## Розділи й приклади коду

У конструкторі запитання згруповані за розділами. Біля кожного розділу видно кількість запитань у банку та кількість у вибірці учня. Порожній розділ, недостатня кількість запитань чи різних типів позначаються попередженням. Запитання можна додати безпосередньо до потрібного розділу; лічильники оновлюються під час перенесення й редагування.

Запитання та варіанти відповідей підтримують багаторядковий текст, пробіли й табуляцію. Формат **Код** вмикає моноширинний шрифт; Tab додає 4 пробіли, Shift+Tab прибирає відступ. Esc, потім Tab переводить фокус до наступного поля. Звичайний текст теж зберігає переноси. Код відображається як текст і не виконується. Валідація нормалізує CRLF, але не обрізає відступи; ліміти — 12000 символів запитання і 6000 на варіант/пояснення.

## HTML-симулятори

**Симулятори → Створити новий** доступно адміністратору. Додайте назву, один самодостатній `.html`/`.htm` файл до 2 МіБ, оберіть одну або кілька паралелей 1–12 та предметів. Тема й опис необов’язкові. Паралелі не залежать від класів зі списками учнів. Збереження чернетки, попередній перегляд, оприлюднення, перейменування без заміни файлу та відновлюване видалення доступні адміністратору.

Оприлюднені симулятори доступні учням, учителям і гостям; каталог має фільтри класу, предмета, теми та пошук. Кнопка **Відкрити** запускає симулятор у новій вкладці з поверненням до каталогу й повноекранним режимом. Це тренувальні вправи без оцінок у журналі.

HTML запускається в ізольованому iframe без доступу до походження платформи, авторизаційних токенів, форм, вкладених фреймів чи довільних API-запитів. Скрипти, стилі, зображення й шрифти можна вбудувати у файл або завантажувати через HTTPS. Локальні папки ресурсів, сховище браузера та серверні запити не підтримуються. Прогрес після закриття не зберігається. Перевіряйте роботу через попередній перегляд до оприлюднення.
